## Install from a package repository

linscp can also come from a package repository, so your system updates it
with everything else. On openSUSE, Fedora, Debian and Ubuntu it is built by
the openSUSE Build Service (its
[install page](https://software.opensuse.org/download.html?project=home:ercorreia&package=linscp)
lists every supported system); on Windows it is on
[Chocolatey](https://community.chocolatey.org/packages/linscp).

<Tabs>
  <TabItem label="openSUSE">
```sh
# Tumbleweed (on Leap 16.0, use 16.0 instead of openSUSE_Tumbleweed)
sudo zypper addrepo https://download.opensuse.org/repositories/home:/ercorreia/openSUSE_Tumbleweed/home:ercorreia.repo
sudo zypper refresh
sudo zypper install linscp
```
  </TabItem>
  <TabItem label="Fedora">
```sh
# Fedora 44 (on Fedora 43, use Fedora_43)
sudo dnf config-manager addrepo --from-repofile=https://download.opensuse.org/repositories/home:/ercorreia/Fedora_44/home:ercorreia.repo
sudo dnf install linscp
```
  </TabItem>
  <TabItem label="Debian">
```sh
# Debian 13
curl -fsSL https://download.opensuse.org/repositories/home:/ercorreia/Debian_13/Release.key | sudo gpg --dearmor -o /etc/apt/keyrings/linscp.gpg
echo "deb [signed-by=/etc/apt/keyrings/linscp.gpg] https://download.opensuse.org/repositories/home:/ercorreia/Debian_13/ /" | sudo tee /etc/apt/sources.list.d/linscp.list
sudo apt update
sudo apt install linscp
```
  </TabItem>
  <TabItem label="Ubuntu">
```sh
# Ubuntu 26.04 (on 26.10, use xUbuntu_26.10)
curl -fsSL https://download.opensuse.org/repositories/home:/ercorreia/xUbuntu_26.04/Release.key | sudo gpg --dearmor -o /etc/apt/keyrings/linscp.gpg
echo "deb [signed-by=/etc/apt/keyrings/linscp.gpg] https://download.opensuse.org/repositories/home:/ercorreia/xUbuntu_26.04/ /" | sudo tee /etc/apt/sources.list.d/linscp.list
sudo apt update
sudo apt install linscp
```
  </TabItem>
  <TabItem label="Windows">
```powershell
# Chocolatey, in an administrator PowerShell
choco install linscp
```
Chocolatey reviews every new version before listing it; while a version is
under review, `choco install` installs the previous one, or none yet.
  </TabItem>
</Tabs>

These packages are for 64-bit PCs (x86_64).

## Check your download (optional)

Two quick checks, if you want to be sure of what you downloaded:

- **The checksum** tells you the file arrived complete and unchanged — a
  broken or truncated download shows up at once.
- **The signature** tells you the files really come from linscp: they are
  signed with linscp's release key, so nobody else can publish a file that
  passes, even if they changed it on the way.

**Checksum.** Each file above lists its SHA-256 checksum. Compare it with the
file you saved:

```sh
sha256sum linscp-*.AppImage
```

On Windows, in PowerShell:

```powershell
Get-FileHash .\linscp-*-setup.exe
```

**Signature.** Download `SHA256SUMS` and its signature `SHA256SUMS.asc` from the
release, get linscp's release key once, and check them. The last command then
checks every linscp file in the folder against the signed list:

```sh
curl -LO https://github.com/99ecarvalho/linscp/releases/latest/download/SHA256SUMS
curl -LO https://github.com/99ecarvalho/linscp/releases/latest/download/SHA256SUMS.asc
gpg --recv-keys A679B8C9915BB5ACDD45F91E207FB492B5B214A9
gpg --verify SHA256SUMS.asc SHA256SUMS
sha256sum --check --ignore-missing SHA256SUMS
```

`gpg` must report a **good signature** from "Eduardo Correia (linscp release
signing)", and the key's fingerprint must be
`A679 B8C9 915B B5AC DD45  F91E 207F B492 B5B2 14A9`. A warning that the key "is
not certified with a trusted signature" is normal: it only means you have not
marked the key as trusted yourself — the fingerprint check is what counts. You can look the
fingerprint up yourself on the key server, by the e-mail address
`ecorreia@apliant.com.br`:
[keys.openpgp.org](https://keys.openpgp.org/search?q=ecorreia%40apliant.com.br).
On Windows, the same `gpg`
commands work in [Gpg4win](https://gpg4win.org/). The key is also in the
repository as
[release-signing-key.asc](https://github.com/99ecarvalho/linscp/blob/main/doc/release-signing-key.asc).

The Windows builds are not code-signed yet, so SmartScreen may warn the first
time you run them.
